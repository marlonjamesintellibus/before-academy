# Lessons

Every lesson — current and future — instantiates these templates; producing a lesson means filling them, not inventing structure.

## Lesson template
Block order: hook → why it matters → objectives (learner-voice, ≤5 bullets) → concept blocks (quick/explore/deeper per [../learning-framework.md](../learning-framework.md) budgets) → diagram (one teaching claim) → misconception callout (one featured ID) → activity → knowledge check → takeaway → next step. Objectives are numbered (LOn) and matrixed to blocks, activities, assessment categories, and remediation targets. One anchor analogy per new concept, with its boundary stated. Structure is stable; wording varies — lessons must not feel templated.

## Activity template
One interaction type per lesson, mapped to objectives; evidence-first feedback ([../feedback.md](../feedback.md)); a deliberate contrast pair wherever a discrimination is being taught; an uncertainty option ("Not enough information" or equivalent) wherever real-world ambiguity exists.

## Assessment template
Category blueprint before questions; difficulty ~40% foundational / 45% applied / 15% challenging; recall questions capped at two per bank; complete remediation mapping; industry variants for applied items ([../assessments.md](../assessments.md)).
