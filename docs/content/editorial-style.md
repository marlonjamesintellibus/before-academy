# Editorial Style & Content Accessibility

## Voice & mechanics
Friendly-expert, second person, contractions welcome; sentence case everywhere (incl. headings/buttons); Oxford comma; numbers under ten as words except data/scores; max one exclamation mark, only at completion moments. Questions invite thinking, never quiz rhetorically.

## Plain language & cognitive accessibility
Grade 8–10 per block (automated readability in content-lint); avg sentence ≤20 words; paragraphs ≤3 sentences; one idea per block. Instructions state the action before the condition. No time pressure anywhere. No idioms that fail translation; no culture-locked examples. Stable structure + varied wording (predictable ≠ templated).

## Inclusive language & the anthropomorphism ban
People-first; gender-neutral "they"; no ability or violence metaphors. AI systems *detect, classify, generate, flag* - never *think, know, understand, believe, want* (feeds M3; lint-able list). Banned words: [../shared/terminology.md](../shared/terminology.md).

## Diagrams & alt text
One teaching claim per diagram (two claims = two diagrams). Alt text ≤125 chars (what it is); long text alternative = complete prose walkthrough delivering the same claim, standalone-readable, versioned with the diagram in the canonical record. Diagram labels use lesson terminology verbatim; reading order matches visual flow; colour never carries meaning alone.

## UX-writing ownership
Interface strings: designer drafts, content writer edits, education lead approves learning-related ones - canonical in [../product/ux-copy.md](../product/ux-copy.md). Educational copy (lesson, feedback, questions): writer drafts, SME + education lead approve. Every string has exactly one home.

## Localization readiness
Written to survive translation: no meaning-bearing wordplay; analogies chosen for cross-cultural familiarity (vending machines, dominoes, weather, restaurants). Locale fields reserved in the schema.
