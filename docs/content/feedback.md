# Feedback

Feedback is where most learning happens. Verbatim UI strings: [../product/ux-copy.md](../product/ux-copy.md). This governs the educational feedback written per question and scenario.

## Principles
Explain, never just judge · **evidence-first**: every explanation names the clue that settles it (trains LO9 in every feedback moment) · honest ambiguity, naming what would settle it · no blame, no gush (encouragement attaches to effort/progress, never identity) · ≤60 words, one idea.

## The formula
**Verdict → Because → Clue → Next**
- Verdict: "Correct - here's why:" / "Not quite - here's the clue:"
- Because: one sentence grounded in the concept
- Clue: the words in the item that decide it
- Next: only when wrong → the remediation link for the category

Example (scenario 6, learner chose AI-assisted): *Not quite - here's the clue: "a fixed menu of options." A decision tree is written rules, so this chat window is traditional software underneath. Review: Traditional software.*

## Partial understanding
Acknowledge what was right first ("You caught the automation layer - there's one more thing happening here"), then apply the formula to the missed element only. Correct the most instructive gap; remediation carries the rest.

## Completion & retry standards
Completion names demonstrated ability ("You can now spot a combined system"), never consumption. Fail state = strengths first, then the plan; the word *fail* never appears. Retry emphasizes fresh questions and readiness; no streaks, timers, or attempt counts in learner copy.
