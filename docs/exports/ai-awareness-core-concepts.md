## Artificial intelligence (AI)

**Systems that find patterns in data to classify, predict, or generate things - instead of only following written rules**

AI is the part of a system whose behaviour was learned from data rather than written down by a person. That single property explains almost everything else about it: why it generalises, why it varies, and why it needs checking.

### Examples

- A spam filter that keeps catching new wording it was never explicitly told about (it handles messages nobody wrote a rule for)
- A photo app that groups pictures of the same person (recognition learned from examples, not from a stored list of faces)
- A chat assistant that phrases the same answer differently each time (output varies for the same input)

> **Speaker notes.** Resist defining AI by what it can do; capability lists date badly and invite the 'complex equals AI' error. Define it by where the behaviour came from. If the audience takes one thing away, make it the question: what patterns would this have learned, from what data, to do this job?

## Traditional software

**Software that follows rules people wrote, so the same input always produces the same output**

Traditional software does exactly what someone wrote down. Same input, same output, every time. Sophistication is not a signal of AI: a complex tax engine is still rules.

### Examples

- A calculator returning a total (same numbers tomorrow, same total)
- A payroll run calculating salaries from timesheets (fixed arithmetic applied on a schedule, however intricate the tax rules are)
- A form that validates a postcode (the accepted patterns were written down by someone)

> **Speaker notes.** The contrast case earns its keep here. Audiences accept 'a calculator is not AI' immediately and resist 'a complex tax engine is not AI', which is precisely why the second example is the one to use.

## Automation

**Using technology to run or connect repeatable tasks with less manual effort**

Automation is about how work flows, not how decisions get made. It can be entirely rule-based, and it can contain AI. The two questions are separate, and answering one does not answer the other.

### Examples

- A confirmation email sent the moment a contact form is submitted (a trigger firing a fixed action, with no judgment involved)
- A nightly report that assembles itself and lands in an inbox (scheduled execution of steps someone defined)
- A support queue that routes tickets by keyword (the routing runs itself, but the rule was written, not learned)

> **Speaker notes.** Put automation and AI side by side rather than in sequence: dominoes next to a forecast. The confusion is not that people think automation is impressive, it is that removing human effort feels like the same thing in both cases.

## Rule-based system

**A system that decides using written if-then rules**

Rules are authored. The system does what someone specified, and it changes only when someone changes the specification.

### Examples

- A bank flagging every transaction above a set amount (one fixed threshold, applied identically to everyone)
- An email filter that blocks a named sender (the condition was typed in by a person)
- A warehouse system reordering stock when the count drops below fifty (fifty is a number someone chose, not a demand forecast)

> **Speaker notes.** The useful diagnostic to offer: ask what would have to happen for this system to behave differently next month. If the answer is 'someone edits it', it is rules.

## Pattern-based system

**A system that decides using patterns learned from many examples**

Pattern-based systems learn their behaviour from examples, so they handle cases nobody anticipated and can be wrong in ways nobody anticipated either.

### Examples

- A fraud check that adapts to new scam patterns without anyone rewriting it (behaviour improved without an edit)
- A support classifier trained on past tickets (the word trained names the mechanism)
- A camera app that finds faces in a photo it has never seen before (it works on images that were not among its examples)

> **Speaker notes.** Pair the benefit and the cost in one breath. Audiences that hear only the benefit come away expecting reliability the mechanism cannot provide.

## Deterministic output

**A result that is always the same for the same input**

Same input, same output. Reproducibility is the signature of authored rules.

### Examples

- Entering the same three amounts and getting the same total (identical output on repeat)
- A payroll run producing the same net pay from the same timesheet (rerun the month and every figure matches)
- A currency converter returning the same amount for the same rate and input (no variation between runs, however many times you ask)

> **Speaker notes.** This is the most actionable idea in the section: it gives a beginner something to actually do when they want to know what they are looking at.

---

## Probabilistic output

**A result based on likelihood, which can vary or be wrong**

Probabilistic systems answer with likelihoods, so the same question can get different answers and some answers will be wrong. That is the design, not a fault.

### Examples

- A chat assistant phrasing the same answer differently each time (the output changed while the input did not)
- A spam filter occasionally catching a real message (a false positive that is expected behaviour, not a bug)
- A voice assistant transcribing the same phrase slightly differently on a second try (identical audio in, different text out)

> **Speaker notes.** The spam false positive is the example to lead with: everyone has lost a real email to a spam folder, and nobody concluded the filter was broken.

## Machine learning

**A way of building AI where systems learn patterns from examples rather than being given rules**

Machine learning is how most AI gets built: fit a model to examples instead of writing the rules. It also means the data is the product.

### Examples

- A recommendation system improving as more people use it (performance changed with data, not with an edit)
- A bank's fraud model retrained each quarter on recent cases (behaviour updated by new examples, not by new rules)
- A logistics tool estimating delivery windows from years of past routes (the estimate came from history; nobody wrote the timings down)

> **Speaker notes.** Level 1 audiences do not need the taxonomy of learning methods. They need the causal link: data shapes behaviour, so data problems become behaviour problems.

---

## Generative AI

**AI that creates new content - text, images, or audio - based on learned patterns**

Generative AI produces new content from learned patterns. It is fluent by construction, and fluency is not evidence that the content is correct.

### Examples

- A tool drafting an email from a one-line instruction (the output did not exist anywhere before)
- An image tool producing a picture from a written description (the picture is composed, not retrieved from a library)
- A meeting tool writing a summary in its own prose rather than quoting lines (the wording is new, so it can be fluent and wrong at once)

> **Speaker notes.** Separate fluency from accuracy explicitly and early. Most audience misjudgment traces back to treating confident prose as a reliability signal.

---

## Human review

**A person checking or deciding on a system's output before it counts**

Human review is where a probabilistic output becomes an accountable decision. Asking who checks the output is often more revealing than asking whether the system uses AI.

### Examples

- A support agent reading and answering a ticket the system routed (a person makes the call that reaches the customer)
- A clinician confirming a flagged scan before it reaches the patient record (the flag is a prompt to look, not a decision)
- An editor approving a drafted product description before it goes live (nothing publishes until a person accepts it)

> **Speaker notes.** This is the bridge to Responsible AI Use. Keep it concrete: name the person and the moment, not the principle.

---

## AI-assisted system

**A product where AI handles part of the work while rules, automation, or people handle the rest**

Most products are combinations: rules, automation, a learned component, and people, layered together. The useful question is not whether a product is AI but which layer is doing the work you care about.

### Examples

- A navigation app: mapping rules, live traffic feeds, and a learned arrival prediction (three mechanisms named in one description)
- A support platform that routes automatically, classifies with a trained model, and hands to an agent (trained names the AI layer, routing names the automation, the agent is the human step)
- An email client with rule-based folders, scheduled send, and a learned spam filter (three mechanisms in one familiar product, only one of them learned)

> **Speaker notes.** Close on this. It reframes the whole topic from a binary label to a reading skill, and it is the idea that transfers to the audience's own procurement and product decisions.
